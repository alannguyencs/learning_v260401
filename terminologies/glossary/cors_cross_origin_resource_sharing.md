# CORS (Cross-Origin Resource Sharing)

A **browser security rule**: by default a page loaded from one **origin** (scheme + domain + port, e.g. `http://localhost:3999`) is *blocked* from calling an API on a *different* origin (e.g. `http://localhost:8999`). The server must opt in by sending `Access-Control-Allow-Origin` headers naming who's allowed — usually configured as **middleware**. It protects users from malicious sites silently calling APIs as them. *Example:* Chloe's React app runs on port 3999 but Alan's API lives on port 8999 — different origins, so her browser refuses the call until Alan's CORS middleware adds a header saying "3999 is allowed." That's also why a random evil site can't quietly hit Alan's API using Chloe's logged-in cookie: the browser won't let it cross origins without permission.
