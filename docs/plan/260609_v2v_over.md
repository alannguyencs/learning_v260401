# Voice-to-Voice Over Mode — Spoken Tutor over Terminology Notes

**Feature**: A single press-to-talk ("Over Mode") voice chatbot. The user speaks
a question, Gemini Live answers in spoken audio, and while answering it can call
two backend tools — BM25 search over the user's terminology notes, and recall of
the current conversation's history.
**Project**: Learning App
**Source design**: [docs/solution.md](../solution.md)
**Ported from**: `api_cognitive_health_chatbot/backend/src/service/v2v_over/`
(backend) and `f42/frontend/src/primitives/hooks/useOverSession.js` +
`composites/V2VOverButton.jsx` (frontend).

---

## Problem Statement

1. The app holds a growing library of `terminologies/notes/*.md`. There is no way
   to *ask* about them conversationally, let alone hands-free by voice.
2. We want a single, focused chat surface: **voice in, voice out, press-to-talk**
   ("voice to voice over"), not a multi-mode text/voice console.
3. The assistant must ground answers in the user's own notes (keyword/BM25, per
   the requirement) and stay coherent across a long spoken session.

---

## Proposed Solution

Port the proven Over Mode pipeline and swap its pgvector RAG tool for a Postgres
BM25 tool. Two function-calling tools are exposed to the Gemini Live session:

1. **`search_notes(query)`** — BM25 keyword retrieval over a new
   `terminology_notes` table that mirrors `terminologies/notes/`.
2. **`get_conversation_history(limit)`** — recent turns of the current voice
   session, read back from a new `voice_conversation_turns` table.

The full rationale, data model, pipeline diagram, and the **button/turn
protocol** to reproduce live in [docs/solution.md](../solution.md) (see §3a there
for the click-state table). This document slices that design into ordered,
shippable stages.

## Current Implementation Analysis

### What Exists (keep as-is)

- **BM25 algorithm** — `terminologies/index/bm25.py` (tokenizer with markdown-link
  stripping + stopwords, RSJ IDF, `k1=1.5`, `b=0.75`). Reused, not rewritten.
- **Terminology parsing** — `terminologies/index/mapping.py::parse_terminology_entries`.
- **Layered backend** — `database.py` (`get_db`, `SessionLocal`, `Base`), the
  `models/ → crud/ → service/ → api/` pattern, `configs.py` settings.
- **Auth** — JWT `access_token` HttpOnly cookie + `authenticate_user_from_request`.
- **Frontend** — React 18 + react-router v6 + Tailwind + axios (`withCredentials`),
  centralized `services/api.js`, `ProtectedRoute`/`AuthenticatedLayout`, the
  `setupProxy.js` `/api` proxy.

### What Changes

| Component | Current | Proposed |
|---|---|---|
| Note retrieval | File-based CLI only (`bm25.py search`) | Also a DB-backed `service/notes_search.py` over a Postgres table |
| BM25 tokenizer/scorer | Lives in `bm25.py` | Extracted to a shared helper used by both CLI and service |
| LLM surface | Text-only (`slide_chat`, `quiz_grader`) | + a realtime Gemini **Live** WebSocket session |
| Frontend chat | Text `ChatPanel` on slides | + a dedicated `/chat` voice page (Over Mode) |
| Reference RAG tool | pgvector `search_knowledge_base` | BM25 `search_notes` (keyword) |

## Implementation Stages

Five stages. Each is independently testable; stages 1–2 have no Gemini/WS
dependency and can land first. "✅ Done when" lists the acceptance gate.

---

### Stage 1 — Notes corpus in Postgres + BM25 tool (Tool #2)

**Goal:** `search_notes(db, query)` returns BM25-ranked notes from a Postgres
table that mirrors `terminologies/notes/`. No LLM, no WebSocket yet.

**To Add**
- `backend/src/utils/bm25_core.py` — extract the tokenizer + BM25 scorer from
  `terminologies/index/bm25.py` so the CLI and the service share one algorithm.
- `backend/src/models/terminology_note.py` — `TerminologyNote` (`id`, `rel_path`
  unique/indexed, `title`, `raw_content` Text, `terminologies` JSON,
  `token_length` Int, `term_freq` JSON, `updated_at`).
- `backend/src/crud/crud_terminology_notes.py` — `list_all`, `upsert`,
  `get_by_rel_path`, `delete_by_rel_path`.
- `backend/src/service/notes_search.py` — `search_notes(db, query, top_k=3)`:
  load `list_all`, compute corpus stats (avgdl, doc_freq) in memory, score, and
  return top-k `{rel_path, title, score, excerpt}`.
- `backend/src/schemas/terminology_note.py` — `NoteHit` response DTO.
- `scripts/sync_terminology_notes.py` — read every `terminologies/notes/*.md`,
  tokenize (shared helper), parse `### Key terminologies`, **upsert** rows, prune
  deleted files. (Exempt from the 300-line cap.)
- Tests: `backend/tests/test_notes_search.py` (SQLite via `conftest.py`) — known
  query ranks the right note first; empty query → no hits.

**To Update**
- `terminologies/index/bm25.py` — import from `utils/bm25_core.py` (or keep a thin
  copy) so behavior stays identical to the on-disk index.
- `scripts/sql/NNN_terminology_notes.sql` — DDL migration for the new table.

**✅ Done when:** `pytest tests/test_notes_search.py` passes and running the sync
script against the 7 existing notes populates the table and returns sensible
rankings from a Python REPL.

### Stage 3 — Gemini Live Over Mode session + both tools (backend)

**Goal:** A working `/api/voice/v2v-over` WebSocket that runs the per-turn Over
Mode loop and wires both tools into the Live config. Validated by script before
any UI.

**To Add** — `backend/src/service/voice_over/` (split to respect the 300-line cap,
mirroring the reference package):
- `client.py` — lazy Gemini Live client + `MODEL`.
- `config.py` — `_over_live_config(voice)`: `response_modalities=["AUDIO"]`,
  voice, in/out audio transcription on, `thinking_budget=0`, **automatic VAD
  disabled**, and the two tool declarations (`search_notes`,
  `get_conversation_history`).
- `pumps.py` — the two streaming pumps, `_await_turn_start` (block until
  `{activity_start}`), `_record_live_turn` (write a row via
  `crud_voice_conversation` on `turn_complete`), and `_handle_tool_call`
  dispatching to `notes_search.search_notes` / `crud_voice_conversation.recent_turns`
  then `session.send_tool_response(...)`.
- `__init__.py` — `run_over_session(ws, *, user, voice, session_id, max_seconds)`:
  the per-turn loop (await `activity_start` → open fresh session → replay
  `activity_start` → emit `session_ready` → run pumps until
  `turn_complete`/`interrupt` → close → loop).
- `resources/voice_system_instruction.md` — tutor persona; instruct the model to
  call `search_notes` before answering term questions and
  `get_conversation_history` for back-references. (Prompt lives under
  `resources/`, per CLAUDE.md — never inlined.)
- `backend/src/api/voice_chat.py` — `WS /api/voice/v2v-over?voice=<name>`: JWT
  cookie gate (close `4401` missing, `4001` bad voice), `accept()`,
  `run_over_session`, error → JSON `{"type":"error"}` + close `1011`, hard cap via
  `asyncio.wait_for`.
- `scripts/smoke_v2v_over.py` — a CLI WS client that drives the
  `activity_start → session_ready → PCM → turn_complete` protocol against a
  recorded WAV, to confirm the loop and tool calls outside the browser.
- Tests: `backend/tests/test_voice_chat_ws.py` — close codes `4401`/`4001` with
  Gemini Live mocked; a mocked `search_notes` tool_call routes to `notes_search`
  and a `send_tool_response` is issued.

**To Update**
- `backend/src/api/api_router.py` — include `voice_chat.router` under `/api`.
- `backend/src/configs.py` + `.env` — `VOICE_LIVE_MODEL`,
  `VOICE_SESSION_MAX_SECONDS`, `VOICE_DEFAULT_NAME`.
- `backend/requirements.txt` — add `google-genai>=1.74.0`.

**✅ Done when:** `pytest tests/test_voice_chat_ws.py` passes and
`scripts/smoke_v2v_over.py` completes a full spoken turn end-to-end (audio out +
a recorded conversation row + at least one successful `search_notes` call).

**Goal:** A single `/chat` page whose mic button reproduces the §3a turn protocol

**To Add**

  `turnActive`-gated send.
- `frontend/src/components/VoiceChat/OverButton.jsx` — port of `V2VOverButton`:
  one mic button branching on state (idle/between→`startTurn`,

- `frontend/src/components/VoiceChat/TranscriptPanel.jsx` + `VoicePicker.jsx`.
- `frontend/src/pages/VoiceChatPage.jsx` + `/chat` route under

- Tests: a Jest test for `useOverSession` state transitions (WebSocket +

**To Update**

**✅ Done when:** in the running app, clicking the mic cycles

## Open Questions

1. **Model pin** — which native-audio Live model version (`VOICE_LIVE_MODEL`)?
   Confirm tool-calling on the pinned version in Stage 3 (the reference's Over
   Mode already depends on it, so this is a smoke test, not a research risk;
   documented half-cascade fallback exists if a version regresses).
2. **Retrieval flavor** — requirement says keyword/BM25; if semantic retrieval is
   later preferred, swap only `service/notes_search.py` (the tool interface is
   stable).
3. **Sync trigger** — run `sync_terminology_notes.py` on deploy only, or also wire
   it into the existing note-authoring skills so the table updates when a note is
   added/edited?
4. **Per-user notes vs shared corpus** — today `terminology_notes` is global; if
   notes become per-user, add a `user_id` scope to the table and `search_notes`.
